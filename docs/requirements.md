# GridLauncher 要件定義書

## 1. 概要

**GridLauncher** は、サイバーパンク風のビジュアルデザインを持つ Android 向けホームランチャーアプリである。
時刻・バッテリー・ストレージ/メモリ使用量・カレンダー・通知バッジなどデバイスの状態を一画面に集約して表示しつつ、
アプリ起動用のグリッド/ドックを備えた「ダッシュボード型ランチャー」を提供する。

- パッケージ名: `com.example.gridlauncher`（**要変更**。公開前に固有のIDへ変更が必要。詳細は9章）
- 開発言語 / UIフレームワーク: Kotlin / Jetpack Compose (Material3)
- 対応端末想定: スマートフォン（縦画面/横画面 両対応。横画面をメイン画面として設計）

## 2. 目的・コンセプト

- 標準ランチャーでは得られない「システムモニター」的な情報密度の高いホーム画面を提供する。
- サイバーパンク/ターミナル風のビジュアル（ネオンアクセントカラー、モノスペースフォント、パネルUI）を統一デザインとする。
- ダーク/ライトテーマ切替、壁紙透過モードなど、見た目のカスタマイズ性を持たせる。

## 3. 動作環境

| 項目 | 値 |
|---|---|
| minSdk | 26 (Android 8.0) |
| targetSdk / compileSdk | 37 |
| ビルドシステム | Gradle (Kotlin DSL) + Version Catalog (`libs.versions.toml`) |
| UI | Jetpack Compose / Material3 |

## 4. 機能要件

詳細は [機能一覧](./features.md) を参照。概要は以下の通り。

1. ホーム画面（グリッド式アプリランチャー、ドック、自由に配置できるウィジェット群、外部ウィジェット）
2. アプリ一覧ドロワー（検索・よく使うアプリ）
3. アプリの配置編集（グリッド/ドック/フォルダへの追加・削除、ウィジェットの追加・移動・リサイズ・削除）
4. 通知バッジ表示・再生中メディアの表示と操作（通知アクセス権限を利用）
5. カレンダー表示（月/週/日の表示切替・スワイプ・端末カレンダーとの連携）
6. デバイスステータス表示（ストレージ/メモリ使用量）
7. クイック設定アクセス（Wi-Fi/画面設定/Bluetooth等への直接遷移、音量・明るさ調整）
8. カスタマイズ（ダーク/ライトテーマ、アクセントカラー2種、壁紙透過モード、アイコン配色、枠線表示など）
9. 初回起動時のオンボーディング（必要な権限・設定への案内）

## 5. 非機能要件

### 5.1 プライバシー・セキュリティ

- **ネットワーク通信を行わない**（`INTERNET` 権限を要求していない）。すべての処理は端末内で完結する。
- 通知の内容そのものは保持・送信せず、「どのアプリに通知/バッジが何件あるか」というパッケージ名と件数のみをメモリ上で保持する。
- 使用する権限は以下の通り、いずれもランチャーアプリとして正当な用途に限定している。

| 権限 | 用途 | 種別 |
|---|---|---|
| `QUERY_ALL_PACKAGES` | インストール済みアプリの一覧取得（アプリドロワー/グリッド表示） | 通常権限（Play Console宣言要） |
| `PACKAGE_USAGE_STATS` | 「よく使うアプリ」の算出 | 特別なアプリアクセス（設定画面から手動許可） |
| `READ_CALENDAR` | カレンダーセクションでの予定表示 | 実行時権限 |
| `REQUEST_DELETE_PACKAGES` | アプリのアンインストール要求（システムの確認画面を表示） | 通常権限 |
| `WRITE_SETTINGS` | QUICK ACCESS の BRIGHT による画面の明るさ変更 | 特別なアプリアクセス（設定画面から手動許可） |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 通知・再生中メディアの監視を安定して続けるための、バッテリー最適化除外の案内 | 通常権限（Play Console宣言要） |
| 通知アクセス (`BIND_NOTIFICATION_LISTENER_SERVICE`) | 各アプリの通知/バッジマーク表示、再生中メディアの表示・操作 | 特別なアプリアクセス（設定画面から手動許可） |
| アクセシビリティサービス (`BIND_ACCESSIBILITY_SERVICE`) | 端末標準の電源メニューを開く（それ以外の用途には使わない） | 特別なアプリアクセス（設定画面から手動許可） |

### 5.2 UI/UX要件

- 縦画面（小）・縦画面（大）・横画面の3つの画面モードを持ち（縦画面は画面幅 600dp を境界値とする）、
  ウィジェットの配置をモードごとに保存する。
- 長押しで編集モードに入り、アプリの削除・空きスロットへの追加、ウィジェットの移動・リサイズ・削除ができる。
- 何もないところの長押しで、ウィジェットの追加・カスタマイズ画面を開くメニューを表示する。
- 上方向スワイプでアプリドロワーを開く。

### 5.3 パフォーマンス・バッテリー

- 定期的な更新（ストレージ/メモリ情報、再生位置のゲージなど）は、ホーム画面が見えている間（ライフサイクルが STARTED 以上）だけ行い、他のアプリの使用中に CPU を起こさない。
- 時刻・バッテリー残量はポーリングせず、システムのブロードキャスト（`ACTION_TIME_TICK` / `ACTION_BATTERY_CHANGED`）で更新する。
- 無限アニメーションは必要な間（演出中・再生中など）だけ生成し、常時動かさない。
- アニメーションは `graphicsLayer` / ラムダ版 `offset {}` / `Canvas` など、再コンポジションを伴わない描画更新を優先する。
- 重い処理（使用状況統計の集計、カレンダーの予定取得など）はメインスレッド以外で行い、加工済みのアプリアイコンはキャッシュして再利用する。

## 6. 制約事項

- サードパーティのランチャーアプリである以上、他アプリのメモリ解放・キャッシュクリアを行う権限はない。「OPTIMIZE SYSTEM」機能は演出のみで、実際のメモリ解放は行わない（自アプリの `System.gc()` も、自プロセスのヒープにしか働かず無用なジャンクを招くため呼ばない）。
- ヘッダーの "TOKYO // MAIN TERMINAL" は固定の装飾テキストであり、現在地などとは連動していない。
- 電源メニューを直接開く公開APIがないため、アクセシビリティサービスの `GLOBAL_ACTION_POWER_DIALOG` を使う（ユーザーによるサービスの有効化が必要）。

## 7. Google Play 配信に向けた要件（未対応・要対応）

本アプリは以下の権限を利用するため、Google Play 審査を通過するには以下の対応がストアコンソール側で別途必要になる。

- [ ] プライバシーポリシーURLの用意とストア掲載情報への登録
- [ ] 通知アクセス権限の使用申告（用途: 通知バッジ表示、再生中メディアの表示・操作）
- [ ] `QUERY_ALL_PACKAGES` 権限の使用申告（用途: ランチャー）
- [ ] アクセシビリティサービスの使用申告（用途: 電源メニューを開く）
- [ ] `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` の使用理由の申告
- [ ] データセーフティフォームの入力（すべて端末内処理、外部送信なしである旨を明記）
- [ ] `applicationId` を `com.example.gridlauncher` から固有のIDへ変更（公開後は変更不可のため必須）
- [ ] `compileSdk`/`targetSdk = 37` が提出時点で正式リリース版のSDKであることの確認

## 8. 既知の技術的負債

- 起動時のインストール済みアプリ一覧の読み込み（全アプリのアイコン加工を含む）はメインスレッドで行っている。バックグラウンドへ移すと起動直後にグリッドが一瞬空になるため、現状は見送っている。
- `AllAppsDrawer.kt` と `AppSelectorDialog.kt` は検索バー付きアプリグリッドという同じ構造を持つ（用途が異なるため即時の統合は非推奨だが、共通コンポーネント化の余地はある）。
- Material3 のデフォルトテーマ（`Theme.kt` の Purple/Pink 配色）は、実際の画面ではほぼ全面的に `LocalCyberColors` で上書きされており、視覚的にはほとんど使われていない。
