# GirdLauncher 要件定義書

## 1. 概要

**GirdLauncher** は、サイバーパンク風のビジュアルデザインを持つ Android 向けホームランチャーアプリである。
時刻・バッテリー・ストレージ/メモリ使用量・カレンダー・通知バッジなどデバイスの状態を一画面に集約して表示しつつ、
アプリ起動用のグリッド/ドックを備えた「ダッシュボード型ランチャー」を提供する。

- パッケージ名: `com.example.girdlauncher`（**要変更**。公開前に固有のIDへ変更が必要。詳細は9章）
- 開発言語 / UIフレームワーク: Kotlin / Jetpack Compose (Material3)
- 対応端末想定: スマートフォン（縦画面/横画面 両対応。横画面をメイン画面として設計）

## 2. 目的・コンセプト

- 標準ランチャーでは得られない「システムモニター」的な情報密度の高いホーム画面を提供する。
- サイバーパンク/ターミナル風のビジュアル（ネオンアクセントカラー、モノスペースフォント、パネルUI）を統一デザインとする。
- ダーク/ライトテーマ切替、壁紙透過モードなど、見た目のカスタマイズ性を持たせる。

## 3. 動作環境

| 項目 | 値 |
|---|---|
| minSdk | 26 (Android 8.0) |
| targetSdk / compileSdk | 37 |
| ビルドシステム | Gradle (Kotlin DSL) + Version Catalog (`libs.versions.toml`) |
| UI | Jetpack Compose / Material3 |

## 4. 機能要件

詳細は [機能一覧](./features.md) を参照。概要は以下の通り。

1. ホーム画面（グリッド式アプリランチャー、ドック、ウィジェット群）
2. アプリ一覧ドロワー（検索・よく使うアプリ）
3. アプリの配置編集（グリッド/ドックへの追加・削除）
4. 通知バッジ表示（通知アクセス権限を利用）
5. カレンダー表示（月送りスワイプ・端末カレンダーとの連携）
6. デバイスステータス表示とメモリ最適化機能
7. クイック設定アクセス（Wi-Fi/画面設定/Bluetooth等への直接遷移）
8. テーマ切替（ダーク/ライト）・壁紙透過モード

## 5. 非機能要件

### 5.1 プライバシー・セキュリティ

- **ネットワーク通信を行わない**（`INTERNET` 権限を要求していない）。すべての処理は端末内で完結する。
- 通知の内容そのものは保持・送信せず、「どのアプリに通知/バッジがあるか」というパッケージ名の集合のみをメモリ上で保持する。
- 使用する権限は以下の通り、いずれもランチャーアプリとして正当な用途に限定している。

| 権限 | 用途 | 種別 |
|---|---|---|
| `QUERY_ALL_PACKAGES` | インストール済みアプリの一覧取得（アプリドロワー/グリッド表示） | 通常権限（Play Console宣言要） |
| `PACKAGE_USAGE_STATS` | 「よく使うアプリ」の算出 | 特別なアプリアクセス（設定画面から手動許可） |
| `READ_CALENDAR` | カレンダーセクションでの予定表示 | 実行時権限 |
| 通知アクセス (`BIND_NOTIFICATION_LISTENER_SERVICE`) | 各アプリの通知/バッジマーク表示 | 特別なアプリアクセス（設定画面から手動許可） |

### 5.2 UI/UX要件

- 縦画面・横画面それぞれに最適化された専用レイアウトを持つ（`HeaderSectionPortrait`/`HeaderSectionLandscape` 等）。
- 画面幅に応じてウィジェット（カレンダー/デバイスステータス）の出し分けを行う（600dp を境界値とする）。
- 長押しで編集モードに入り、アプリの削除・空きスロットへの追加ができる。
- 上方向スワイプでアプリドロワーを開く。

### 5.3 パフォーマンス

- 頻繁に再計算される値（メモリ/ストレージ情報）は5秒間隔のポーリングに留め、不要な再計算を避ける。
- アニメーションは `graphicsLayer` / ラムダ版 `offset {}` など、再コンポジションを伴わない描画更新を優先する。

## 6. 制約事項

- サードパーティのランチャーアプリである以上、他アプリのメモリ解放・キャッシュクリアを行う権限はない。「OPTIMIZE SYSTEM」機能は自アプリの `System.gc()` 呼び出しと、その前後の実メモリ空き容量の実測差分を表示する機能であり、システム全体のキャッシュを強制的に解放するものではない。
- 天気表示（`HeaderSectionPortrait` 内の "22° // TOKYO"）は現時点ではハードコードされたプレースホルダーであり、実際の気象データとは連動していない。

## 7. Google Play 配信に向けた要件（未対応・要対応）

本アプリは以下の権限を利用するため、Google Play 審査を通過するには以下の対応がストアコンソール側で別途必要になる。

- [ ] プライバシーポリシーURLの用意とストア掲載情報への登録
- [ ] 通知アクセス権限の使用申告（用途: 通知バッジ表示）
- [ ] `QUERY_ALL_PACKAGES` 権限の使用申告（用途: ランチャー）
- [ ] データセーフティフォームの入力（すべて端末内処理、外部送信なしである旨を明記）
- [ ] `applicationId` を `com.example.girdlauncher` から固有のIDへ変更（公開後は変更不可のため必須）
- [ ] `compileSdk`/`targetSdk = 37` が提出時点で正式リリース版のSDKであることの確認

## 8. 既知の技術的負債

- `HeaderSectionPortrait.kt` と `HeaderSectionLandscape.kt` は時刻/バッテリー表示ロジックがほぼ重複している。将来的に共通ロジックを抽出する余地がある。
- `AllAppsDrawer.kt` と `AppSelectorDialog.kt` は検索バー付きアプリグリッドという同じ構造を持つ（用途が異なるため即時の統合は非推奨だが、共通コンポーネント化の余地はある）。
- Material3 のデフォルトテーマ（`Theme.kt` の Purple/Pink 配色）は、実際の画面ではほぼ全面的に `LocalCyberColors` で上書きされており、視覚的にはほとんど使われていない。

## 9. 変更履歴（このセッションでの対応）

- 通知バッジ（未読件数）を通知マークとして表示するよう `CyberNotificationListener` のフィルタ条件を調整
- OPTIMIZEボタンに演出アニメーションと実メモリ解放量の表示を追加
- カレンダーセクションを月単位の横スワイプ（`HorizontalPager`）に対応
- コンパイラ警告・Android Lint警告の解消（35件中31件を解消、残り4件は依存バージョンアップ提案のみ）
- 未使用の `QuickAccessSectionPortrait` / `QuickButtonPortrait` / `colors.xml` を削除
- KDocコメントの欠落・不整合を修正
